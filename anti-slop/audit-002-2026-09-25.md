# Post-build UI audit 002

Mode: **AFTER**. The Plex browser flow and the share-only fallback were run
against a fake Pi player and fake Plex resources before this review. No UI
changes were made in response to this audit. Findings 1 and 2 were already
reported in audit 001 and remain unapproved.

**Design read:** A low-light, touch-first bedside remote for a listener using
a phone or Kindle Fire. The owner supplied the dim, calm direction. Dials:
**ENERGY 1 / RHYTHM 1 / MOTION 1**.

**Decision reasons:** Matte dark olive reduces night glare; warm beige calls
out the bedtime action and keyboard focus; text labels avoid ambiguous
icons; a separate Plex connection area makes sign-in and emergency silence
available before protected playback; folders follow server, library, show,
season, episode; panels stack on phones and sit side by side when space
allows; 48 px touch heights and system type work offline.

## Numbered findings

1. **HIGH, R-25 (human/non-text contrast, inherited):**
   `bedside_audio/static/style.css:5-6,275-285,384-393`. Unfocused button
   backgrounds differ from their panel by **1.18:1**; their shared border
   is **2.06:1** against the panel and **1.76:1** against the control.
   These miss the 3:1 non-text contrast bar. New Plex text and the hosted
   link pass normal-text contrast (at least **9.64:1**).
2. **LOW, R-29/R-31 (palette consistency, inherited):**
   `bedside_audio/static/style.css:318-344`. Chromium keeps the native
   range input appearance, so the visible slider thumbs are blue instead
   of the defined warm accent; no product purpose explains the second
   accent.
3. **LOW, R-05/R-20 (mobile task hierarchy, new):**
   `bedside_audio/static/index.html:23-67` and
   `bedside_audio/static/style.css:81-163`. The signed-in account panel
   occupies **291 px** on a 320 x 740 viewport; Start bedtime begins at
   **551 px** and the player at **632 px**, pushing transport below the first
   screen even though account management is secondary after sign-in.

### Browser click-through evidence

- Before sign-in, **Silence Pi** returned visible confirmation while the protected player stayed hidden. **Connect to Plex** showed a real short code, a validated HTTPS Plex link, and a five-minute countdown; polling transitioned to an authenticated browser session. No Plex or server token appeared in the DOM or browser cookies.
- Browsing exposed two Plex servers, then TV libraries, shows, seasons, and ordered episodes. Human-readable breadcrumbs replaced opaque identifiers. Starting bedtime did not auto-play; selecting an episode did. Reloading the browser left the Pi-owned player running.
- Next/Previous changed episodes; Pause/Play, seek to 0:42, volume to 33%, Set timer, and Cancel timer updated backend state and visible UI.
- **Sign out** stopped playback and hid media names. **Disconnect Plex** opened a confirmation; Escape and Cancel kept the account, while Confirm removed it and hid protected media. The unauthenticated emergency stop remained available.
- With Plex disabled, the connection panel was hidden and the local file could still be selected, played, and silenced. At 320 px and 1024 px neither mode overflowed horizontally. No browser console errors were observed.
